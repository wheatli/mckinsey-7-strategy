# 第 7 步：提出建议（Develop Recommendations）

<HARD-GATE>
进入本步骤前必须满足：
- 存在 `docs/strategy/<code>/step-6-synthesis.md`
- step-6 的主结论是封闭式判断
- 红队反对已回应 ≥ 2 条

未满足 → 拒绝执行，回退到 step-6。
</HARD-GATE>

## 本步骤的目标

把 step-6 的金字塔结论翻译成**最终交付物**——一份可独立成篇的建议书，包含：
- 执行摘要（SCP 一页，3 个理由 + 3 个数字）
- 实施路径（每阶段都有决策门）
- 资源需求 + 风险应对 + KPI + Next 7 Days

**完成的标准**：决策者拿到这份文档，无需读 step-1~6 也能做决策。

## 方法论核心

1. **SCP 结构**（Situation - Complication - Proposal）：把金字塔翻译成商业故事
2. **结论先行**：建议书第一页就给答案 + 3 个理由，不让决策者翻到最后才知道
3. **决策门（Stage Gate）**：每个阶段都有"达到 X 才能进入下一阶段"，不留单程票
4. **先行指标 + 滞后指标**：KPI 必须能早预警，不能只看年度结果
5. **Next 7 Days 具体化**：写到具体会议、文件、邮件，不写"启动项目"

## 引导式对话流程

### Step 7.1 — 复制模板 + 加载金字塔

读取插件模板 `templates/07-recommendation.md`，复制到 `docs/strategy/<code>/step-7-recommendation.md`。

读取：
- `step-6-synthesis.md`：主结论、3 论点
- `step-1-problem.md`：决策者画像、SCQA
- `step-5-analysis.md`：关键数字
- `step-6-synthesis.md`：残留不确定性 → 风险章节种子

### Step 7.2 — 写执行摘要（一页纸）

引导用户写一页 SCP：

> **S（情境）**：基于 step-1 的 SCQA 之 S，加 step-5 的关键数据补充
>
> **C（冲突）**：基于 step-1 的 SCQA 之 C，加 step-5 中证伪/证实的关键发现
>
> **P（建议）**：基于 step-6 主结论。**必须以动词起首**——"建议进入 / 投入 / 暂缓 / 调整……"

填模板章节 1。

#### 三大理由

> 把 step-6 的 3 个论点改写成"建议成立的 3 个理由"，用决策者听得懂的话。

#### 三个关键数字

> 用 3 个最有说服力的数字背书建议。例如：
> - "3 年净收益 ¥X"（财务）
> - "回本周期 Y 个月"（时间）
> - "成功概率 Z%（基于历史可比项目）"（风险）

强制数字落地，不接受"显著提升"这种空话。

### Step 7.3 — 建议详述

#### 7.3.1 我们建议什么

> 具体到可执行：动作 + 主体 + 时间 + 度量。
>
> 例如不能写"加大市场投入"，应写"在 Q3 把数字营销预算从 ¥X 提到 ¥Y，重点投放渠道 Z，由营销负责人 P 负责"。

#### 7.3.2 我们不建议什么（**必做**）

> 列出 step-3 砍掉的方案、step-6 红队反对中讨论过但被排除的方案。
>
> 这能减少决策者再次质疑的成本——ta 想到的反对方案，你已经讨论过并解释了为什么不选。

引导用户列至少 2 个备选 + 排除理由。

### Step 7.4 — 实施路径（含决策门）

引导用户分 4 阶段（准备 / 试点 / 推广 / 复盘），每阶段必填：

- 时间窗口（具体到 0-30d, 1-3m 等）
- 关键动作（动词起首）
- 责任人（自然人）
- 衡量指标（先行指标）
- **决策门**：达到什么条件才能进入下一阶段，未达到怎么办

填模板章节 3。

**关键挑战**：如果用户写"按计划推进"，挑战 ta：达到什么具体指标才算"按计划"？没达到怎么办？

### Step 7.5 — 资源需求

填模板章节 4：资金、人力、时间、外部依赖。强调**分阶段投入**——不要一次性 all-in。

### Step 7.6 — 风险与应对（带早期信号）

把 step-6 的"残留不确定性"清单转化为风险表。每个风险必须有：

- 概率（高/中/低）
- 影响（高/中/低）
- 应对措施（具体动作）
- **早期信号**：什么观察到的信号会触发应对？

例如：

| 风险 | 早期信号 |
| --- | --- |
| 用户接受度低于预期 | 试点前 4 周转化率连续 ≤ X% |
| 竞争对手抢先 | 竞品发布同类产品 / 招聘对应岗位 |

强制写早期信号——没信号的风险表是装饰，不是工具。

### Step 7.7 — KPI 跨四维度

引导用户为业务 / 财务 / 客户 / 团队四维度各设 1-2 个 KPI，并填 30d / 90d / 1y 目标。

挑战：

> KPI 里有先行指标吗？如果全是"年收入"这种滞后指标，等你看到下滑就来不及了。加 1 个先行指标（如周活、转化率、NPS）。

### Step 7.8 — Next 7 Days

> 假设决策者今天批准了，第一周必须发生的具体动作是什么？写到：
>
> - Day 1：……（具体到一个会议、一封邮件、一个决定）
> - Day 3：……
> - Day 7：……

不接受"启动项目"或"开始准备"这种空话。

### Step 7.9 — 走自检

对照模板自检清单逐项过。重点：
- 一页摘要可独立成篇
- "我们不建议什么"列了至少 2 项
- 每阶段都有决策门
- 风险都有早期信号
- KPI 含先行指标
- Next 7 Days 具体

### Step 7.10 — 与决策者确认

提醒用户：

> 这份建议书的最终版应该与决策者**口头过一遍**——读一页摘要 + 走一遍 Next 7 Days，看 ta 在哪里皱眉头。
>
> ta 的反应会暴露你这份建议里**没说清楚**的地方，回来修订。

## 自检清单（完成门禁）

- [ ] 一页执行摘要可独立成篇
- [ ] SCP 三段齐全，P 是动词起首
- [ ] "我们不建议什么"列了 ≥ 2 项
- [ ] 每阶段都有决策门和衡量指标
- [ ] ≥ 3 个主要风险，每个配早期信号
- [ ] KPI 跨业务/财务/客户/团队四维度，含 ≥ 1 个先行指标
- [ ] Next 7 Days 具体到会议/文件/邮件
- [ ] 已与决策者过一遍（或注明"待过"）

## 反模式（红旗）

| 红旗信号 | 真相 |
| --- | --- |
| 建议是"需要进一步研究" | 等于没建议；至少给暂定建议 |
| 没"我们不建议什么" | 决策者会问，提前回答 |
| 实施路径无决策门 | 单程票，不是建议 |
| KPI 全是滞后指标 | 加先行指标才能早预警 |
| Next 7 Days 写"启动项目" | 太空，写到具体会议 |
| 风险栏写"市场不确定性" | 万能套话，写到具体场景和阈值 |
| 资源需求一次性 all-in | 应分阶段投入，与决策门挂钩 |
