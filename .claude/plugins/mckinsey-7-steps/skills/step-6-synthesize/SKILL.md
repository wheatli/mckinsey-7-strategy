# 第 6 步：综合调查结果（Synthesize Findings）

<HARD-GATE>
进入本步骤前必须满足：
- 存在 `docs/strategy/<code>/step-5-analysis.md`
- step-5 自检通过（每个证实的假设都检视了反向证据）

未满足 → 拒绝执行，回退到 step-5。
</HARD-GATE>

## 本步骤的目标

把 step-5 散落的假设结论，**向上归纳**为：
- 1 个回答焦点问题的主结论（金字塔尖）
- 3 个 MECE 的支柱论点（金字塔第二层）
- 每个论点的实证支撑链 + 红队回应

**完成的标准**：金字塔结构闭环，主结论是封闭式判断，至少 2 条红队反对意见已被回应。

## 方法论核心

1. **金字塔原理**：结论先行，向上归纳——主结论 ← 论点 ← 论据
2. **3 个论点法则**：2 太单薄，4+ 太散，3 是讲清楚一件事的甜蜜点
3. **MECE 论点**：3 个论点之间互斥不重叠，合起来充分支撑主结论
4. **So What 链条闭合**：从底层 H1 → 论点 A → 主结论，每一跳都问"所以呢？"
5. **红队思维**：主动列出最强反对意见，并在现有证据基础上回应

## 引导式对话流程

### Step 6.1 — 复制模板 + 加载分析结论

读取插件模板 `templates/06-synthesis-pyramid.md`，复制到 `docs/strategy/<code>/step-6-synthesis.md`。

读取 `step-5-analysis.md`：
- 每个假设的最终结论 + So What
- 意外发现清单

也读取 `step-1-problem.md` 的"焦点问题"原文。

### Step 6.2 — 草拟主结论

向用户输出：

> 现在我把 step-5 的所有 So What 列出来：
>
> - H1 的 So What：……
> - H3 的 So What：……
> - …
>
> 加上意外发现：……
>
> 焦点问题：「…」

然后引导用户用一句话回答焦点问题：

> 用一句话回答焦点问题。要求：
> - 是封闭式（yes/no 或具体选项），不是"需要进一步研究"
> - 自带行动方向（"建议进入 X 市场，但仅限 Y 渠道"）
> - 一个外行能听懂

如果用户给的是开放式或回避式答案，挑战 ta：基于现有证据**倾向**于什么？把"暂定建议"也算作主结论。

写入模板章节 1。

### Step 6.3 — 提炼 3 个支柱论点

引导用户从"主结论"反推：要让这个主结论成立，必须证明哪 3 件事？

启发式：

> 我们倒着来。如果你的主结论是「建议进入 X 市场」，那要让 ta 站得住脚，至少必须回答：
>
> - 论点 A：市场是否值得进？（需求侧）
> - 论点 B：我们是否打得赢？（竞争 + 能力侧）
> - 论点 C：进的方式是否可控？（执行 + 风险侧）

让用户自己写 3 个论点。每个论点必须是**判断句**（"市场已饱和"），不是描述句（"市场份额 60%"）。

写入章节 2。

### Step 6.4 — 给每个论点配证据

对每个论点，引导用户从 step-5 的假设结论里挑出支撑它的假设：

> 论点 A：「…」
>
> step-5 里哪些假设的结论支撑这个论点？把 H 编号 + 一句话结论列出来。

填到模板章节 2 各论点下"支撑证据"小节。

#### MECE 检查

问用户：

> 同一个 H? 不应该同时出现在两个论点下面。如果出现了，说明论点之间不互斥，需要重新切分。

如果有重叠，引导重新组织论点边界。

### Step 6.5 — 画金字塔结构图

把模板章节 3 的 ASCII 图填好——主结论 → 3 论点 → 每个论点下的 H?。视觉上让用户看到结构。

### Step 6.6 — 走逻辑链闭环检验

逐条走模板章节 4 的"跳跃"表：

> 从 H1 推出论点 A，逻辑跳跃成立吗？请用一句话写出"因为 H1 ……所以论点 A ……"

如果用户说不出来，说明这条跳跃不成立——回退去找更直接的证据，或调整论点表述。

### Step 6.7 — 红队反对（**必做**）

向用户挑战：

> 现在你是反对者。看着这份金字塔，你能想到的**最强 2 条反对意见**是什么？
>
> 提示：
> - 反对意见可能针对主结论本身（"这个判断方向就错了"）
> - 也可能针对某个论点（"论点 B 的证据不足"）
> - 也可能针对前提（"主结论隐含的假设 X 不成立"）

让用户写 2 条反对意见，然后逐条回应：

> 用现有证据如何回应这条反对？回应是"完全反驳"还是"承认但削弱"？

填到模板章节 5。

### Step 6.8 — 残留不确定性

问用户：

> 主结论成立有什么前提条件？哪些假设还没完全验证？哪些是适用边界？

把"未消除的风险"明确列出——这些会在 step-7 转化为风险章节和决策门。

填到章节 6。

### Step 6.9 — 走自检

按模板自检清单逐项确认。重点：主结论封闭式、论点 = 3、MECE、红队 ≥ 2 条、外行能听懂。

## 产出物

- 模板：插件 `templates/06-synthesis-pyramid.md`
- 落盘：`docs/strategy/<code>/step-6-synthesis.md`

## 自检清单（完成门禁）

- [ ] 主结论是封闭式判断（yes/no 或具体选项）
- [ ] 论点 = 3（如果 2 或 4，写明理由）
- [ ] 论点之间 MECE
- [ ] 每个论点至少 1 个 step-5 假设支撑
- [ ] 至少 2 条红队反对已回应
- [ ] 主结论一句话能让外行听懂
- [ ] 残留不确定性清单已列出

## 反模式（红旗）

| 红旗信号 | 真相 |
| --- | --- |
| 主结论是"需要进一步研究" | 没结论；至少给暂定判断 |
| 论点是数据描述 | 应是判断；改写 |
| 反对意见栏空着 | 在自我证实；红队是必做 |
| 论点互相重叠 | MECE 没做好，重新切分 |
| 论点和论据用错位（循环论证） | 把"因为 H1 所以 H1"改写为更上一层的判断 |
| 4+ 个论点 | 太散，合并到 3 个；如必须 4，说明你的拆解维度不正交 |

## 完成后交接

向用户输出：

> ✅ Step-6 完成。金字塔结构成型：
>
> - 主结论：「…」
> - 论点 A：「…」
> - 论点 B：「…」
> - 论点 C：「…」
> - 红队反对已回应 X 条
>
> 下一步进入 **step-7: 提出建议**——把金字塔翻译成可执行的建议书：执行摘要、行动路径、风险与衡量指标。预计 20-30 分钟。
>
> 这是最后一步了。继续吗？

确认后，调用 `step-7-recommend` skill。

输入给下一步：
- `<code>`
- `step-6-synthesis.md` 路径
- 主结论 + 3 论点
- 残留不确定性清单
- step-1 决策者画像（建议书的对象）
