## 1. 议题树（Issue Tree）

> 把焦点问题拆解为 MECE（互斥且穷尽）的子问题，**每个子问题在拆下一层时也要 MECE**。深度 2-4 层为宜，叶子节点必须是可独立验证的假设。

```
焦点问题：__________________________________________
│
├── 一级子问题 A
│   ├── 二级子问题 A.1
│   │   ├── 假设 A.1.1：______（可证伪表述）
│   │   └── 假设 A.1.2：______
│   └── 二级子问题 A.2
│       └── 假设 A.2.1：______
│
├── 一级子问题 B
│   ├── 二级子问题 B.1
│   │   └── 假设 B.1.1：______
│   └── 二级子问题 B.2
│       └── 假设 B.2.1：______
│
└── 一级子问题 C
    └── ...
```

## 2. 拆解逻辑说明

> 解释你为什么这样拆。常见拆解维度（择一或组合）：

- 流程维度：价值链 / 漏斗（获客→转化→留存→变现）
- 组织维度：人 / 财 / 物 / 事
- 财务维度：收入 = 量 × 价；利润 = 收入 - 成本
- 因果维度：原因 / 结果
- 时间维度：现状 / 短期 / 长期
- 利益相关方维度：客户 / 员工 / 股东 / 监管

## 3. MECE 自检

- [ ] 各一级子问题之间**互斥**：没有重叠
- [ ] 各一级子问题之和**穷尽**：合起来能完整回答焦点问题
- [ ] 同一层级使用同一拆解维度（不要混用维度）
- [ ] 每个叶子假设都是**可证伪**的陈述（"X ≥ Y"，而非"X 比较好"）

## 自检清单（完成门禁）

- [ ] 议题树深度 ≥ 2 层
- [ ] 所有叶子节点都已转化为可证伪的假设
- [ ] 每个一级子问题都通过 MECE 检查
- [ ] 至少识别出 5 个待验证假设
- [ ] 每个假设都标注了初始信心和证据需求

## 反模式（红旗）

| 红旗信号 | 真相 |
| --- | --- |
| 子问题是动词性的"做 X" | 应是疑问句"是否 / 多少 / 何时" |
| 同层 5+ 个分支 | 拆得太细，合并；或维度不一致 |
| 同层 1 个分支 | 没拆，回去补全 |
| 假设写成"X 很重要" | 不可证伪，应改为"X 对 Y 的贡献 ≥ Z%" |
| 直接套 4P / 7S 框架 | 框架应服务问题，而非反过来；先想拆解维度再选框架 |
