## 1. 原始 idea / 触发事件

> 用 1-3 句话写下用户最初提出的问题或想法。**不加修饰，不下判断**。

## 2. SCQA 四要素

| 要素 | 内容 |
| --- | --- |
| **S 情境（Situation）** | 当前业务/行业/团队所处的稳定状态是什么？ |
| **C 冲突（Complication）** | 什么变化打破了稳定，使决策变得必要？ |
| **Q 问题（Question）** | 因为这个冲突，我们必须回答的**焦点问题**是什么？ |
| **A 暂定答案（Answer）** | 当前直觉答案（用于后续证伪/证实，不是最终结论） |

## 3. 决策者画像

| 维度 | 内容 |
| --- | --- |
| 决策者是谁 | 姓名/岗位 |
| 决策者关心什么 | 3 个最关心的指标或维度 |
| 决策标准 | 决策者会用什么标准判断"这是好建议"？ |
| 时间压力 | 何时必须给出结论？ |
| 历史包袱 | 决策者过去在类似问题上做过什么决定？ |

## 4. 边界与约束

- **范围内（In Scope）**：本次分析必须覆盖的领域
- **范围外（Out of Scope）**：明确不分析的领域，及理由
- **资源约束**：可用预算、时间、人力、数据
- **不可违反的硬约束**：法律、合规、伦理、战略红线

## 5. 成功标准（Definition of Done）

> 本次战略分析"完成"必须满足的可观测条件。每条都应可验证。

- [ ] 条件 1：……
- [ ] 条件 2：……
- [ ] 条件 3：……

## 6. 焦点问题（最终精炼版）

> 一句话写出本次分析要回答的核心问题，**必须是 yes/no 或具体选项的形式**，避免开放式。

```
焦点问题：__________________________________________
```

## 自检清单（完成门禁）

- [ ] SCQA 四要素都填了，且 Q（焦点问题）是封闭式
- [ ] 决策者明确（不是抽象"公司"或"团队"）
- [ ] 范围外至少列了 1 项，并写明为什么不做
- [ ] 成功标准每条都可观测、可验证
- [ ] 焦点问题与原始 idea 相比，更具体、更可解
- [ ] 与决策者口头确认过焦点问题（或注明"待确认"）

## 反模式（红旗）

| 红旗信号 | 真相 |
| --- | --- |
| 焦点问题是 "如何提升 X？" | 太开放，应改为 "是否应该投入 Y 来提升 X，且边界为 Z" |
| 决策标准写成 "符合公司战略" | 太空，应具体到指标（ROI ≥ 15%、6 个月回本…） |
| 范围外为空 | 没思考过，几乎肯定后面会失控 |
| 跳过 SCQA 直接写答案 | 在用直觉裸奔，后面拆解会跑偏 |
