# 第 2 步：分解问题（Structure the Problem）

<HARD-GATE>
进入本步骤前必须满足：
- 存在 `docs/strategy/<code>/step-1-problem.md`
- step-1 自检清单全部通过（焦点问题是封闭式）

未满足 → 拒绝执行，要求先完成或重做 step-1。
</HARD-GATE>

## 本步骤的目标

把 step-1 的焦点问题，按 MECE 原则拆解为一棵 2-4 层的议题树，并把每个叶子节点转化为**可证伪的假设**。

**完成的标准**：`docs/strategy/<code>/step-2-tree.md` 通过自检，且至少识别出 5 个待验证假设。

## 方法论核心

1. **MECE**（Mutually Exclusive, Collectively Exhaustive）：互斥（不重叠）+ 穷尽（合起来覆盖全部）
2. **维度一致性**：同一层用同一拆解维度（流程 / 财务 / 组织 / 因果 / 时间 / 利益相关方），不能混用
3. **叶子即假设**：叶子必须是"X ≥ Y" 这种可证伪陈述，而非 "X 很重要" 这种不可证伪
4. **假设驱动**：先有假设，再去找证据验证；而不是堆数据看会冒出什么

## 引导式对话流程

### Step 2.1 — 复制模板 + 加载焦点问题

读取模板 `templates/02-issue-tree.md`，复制到 `docs/strategy/<code>/step-2-tree.md`。

读取 `step-1-problem.md` 的"焦点问题"，填入新文档元信息。

### Step 2.2 — 选拆解维度

向用户展示 6 种常见拆解维度（用 `AskUserQuestion`，让用户选 1 种）：

> 焦点问题：「<焦点问题>」
>
> 我们用哪个维度做第一刀？
>
> 1. **流程维度**（价值链 / 漏斗）：适合优化类问题，如"获客→转化→留存"
> 2. **财务维度**（量×价 / 收入-成本）：适合赚钱类问题
> 3. **组织维度**（人/财/物/事）：适合资源调配类问题
> 4. **因果维度**（原因/结果）：适合问诊式问题
> 5. **时间维度**（短期/中期/长期）：适合规划类问题
> 6. **利益相关方维度**（客户/员工/股东/监管）：适合冲突协调类问题

记录选择和理由到模板的"拆解逻辑说明"表。

### Step 2.3 — 拆出第一级（3 个左右）

基于选定维度，引导用户拆出 3 个左右的一级子问题。**每个子问题必须是疑问句**（"是否 / 多少 / 何时 / 哪里"）。

如果用户给出动词性表述（"做 X"），帮 ta 改写为疑问句。

写入议题树的一级。

### Step 2.4 — 对一级做 MECE 自检

问用户（一题一题问）：

1. 这 3 个一级子问题之间，有没有重叠？（互斥检查）
2. 这 3 个合起来，能完整回答焦点问题吗？还是漏了什么？（穷尽检查）

如果不互斥，引导合并。如果不穷尽，引导补一个"其他"或具体补项。

### Step 2.5 — 拆第二级

对每个一级子问题，问用户：

> 这个子问题（"<子问题 A>"），可以再用什么维度往下拆一层？

继续应用维度一致性原则：**同一个一级问题下的二级子问题，必须用同一个拆解维度**。

写入议题树二级。

判断是否需要拆第三级：
- 二级子问题已经能转化为可证伪的具体假设 → 停在二级
- 二级仍然太抽象 → 拆三级

最深 4 层，超过 4 层说明颗粒度有问题。

### Step 2.6 — 把叶子转成假设

对每个叶子节点，引导用户写出"可证伪的假设陈述"。给标准范式：

| 不好的假设 | 好的假设 |
| --- | --- |
| 客户体验很重要 | 提升客户满意度 NPS 10 分能让复购率提升 ≥ 20% |
| 团队需要扩张 | 当前 5 人团队的瓶颈在前端，再加 2 个前端能让交付速度提升 ≥ 50% |
| 价格太贵 | 客单价降到 X 能让转化率从 Y 提升到 Z，但毛利仍为正 |

**关键三要素**：可量化、有方向、可证伪。

写入"假设清单"表，并标注初始信心（高/中/低）和"证据需求"（要拿到什么数据才能验证）。

### Step 2.7 — 走 MECE 自检 + 完成门禁

引导用户对照模板的"MECE 自检"和"自检清单"逐项确认。

特别关注：
- 同层是否同维度
- 是否同层有 5+ 分支（颗粒太细，合并）
- 是否同层只有 1 分支（没拆，回去）
- 假设是否都可证伪

## 产出物

- 模板：`templates/02-issue-tree.md`
- 落盘：`docs/strategy/<code>/step-2-tree.md`

## 自检清单（完成门禁）

- [ ] 议题树深度 ≥ 2 层
- [ ] 每层用统一拆解维度
- [ ] 一级 MECE 检查通过（互斥 + 穷尽）
- [ ] 至少 5 个叶子假设，且全部可证伪
- [ ] 每个假设标注了初始信心和证据需求
- [ ] 用户口头确认议题树覆盖了焦点问题的核心方面

## 反模式（红旗）

| 红旗信号 | 真相 |
| --- | --- |
| 直接套用 4P / 7S / SWOT | 框架应服务问题；先选维度，再判断是否套现成框架 |
| 一级拆出 6+ 分支 | 维度不一致或过细，合并 |
| 假设是"X 很重要" | 不可证伪，加量化阈值 |
| 叶子节点已经是动作而非疑问 | 越权到 step-7（建议），回退 |
| 树拆得很深但没有量化 | 在演结构主义；强制每个叶子加可观测指标 |

## 完成后交接

向用户输出：

> ✅ Step-2 完成。议题树共 X 层，识别出 Y 个待验证假设。
>
> 下一步进入 **step-3: 优先排序**——我们会用"影响度 × 可解性"矩阵，从 Y 个假设里挑出 ≤ 7 个 Key Drivers。预计 10-15 分钟。
>
> 继续吗？

确认后，调用 `step-3-prioritize-issues` skill。

输入给下一步：
- `<code>`
- `step-2-tree.md` 路径
- 假设清单（编号 + 陈述 + 初始信心）
