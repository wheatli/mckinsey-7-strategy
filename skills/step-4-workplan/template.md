## 2. 输出形式约定

每个假设的分析输出必须是**结论先行**的形式，而不是"分析过程"。常见形式：

- **一张图 + 三句话**：用图说明数据，用话说明 So What
- **一个数字 + 假设清单**：估算结果 + 推导用到的关键假设
- **2×2 矩阵**：分类对比
- **决策树**：if-then 结构的判断
- **故事板（5 张幻灯片）**：用于模拟最终汇报

## 3. 数据获取策略

| 数据来源类型 | 优先级 | 触达方式 | 时间成本 |
| --- | --- | --- | --- |
| 内部数据库 / BI | 高 | 已有访问 | 低 |
| 业务专家访谈 | 高 | 30 分钟会议 × N | 中 |
| 客户/用户调研 | 中 | 问卷 / 1对1 | 中-高 |
| 公开行业报告 | 中 | 桌面研究 | 低 |
| 第三方付费数据 | 低 | 采购流程 | 高 |

## 4. 风险与依赖

| 风险 | 概率 | 影响 | 缓解措施 |
| --- | --- | --- | --- |
| 数据拿不到 | 中 | 高 | 先做粗估，标注假设；同时启动数据申请 |
| 关键访谈推迟 | 中 | 中 | 提前 1 周预约，准备替代受访者 |
| 假设跑偏 | 低 | 高 | 第 5 步设中期检查点 |

## 5. 中期检查点（Mid-point Check）

- 日期：`YYYY-MM-DD`（约总工期 50%）
- 触发条件：
  - 任一关键假设被证伪 → 回到 step-2 重做议题树
  - 数据获取失败 → 切换到粗估或调整假设范围
  - 时间超期 30%+ → 砍掉低优先级假设

## 6. 时间线（甘特图占位）

## 自检清单（完成门禁）

- [ ] 每个保留假设都有一行计划
- [ ] 每行都明确了"输出形式"（不是"做分析"）
- [ ] 总工时不超过可用资源（含 20% buffer）
- [ ] 设置了至少一个中期检查点
- [ ] 数据来源不是"再说"或"网上找"
- [ ] 责任人到自然人（不是"团队"）

## 反模式（红旗）

| 红旗信号 | 真相 |
| --- | --- |
| 输出形式写成"分析报告" | 太空，写成"一张图 + 三句结论"或具体形态 |
| 工时估计全是 1 周 | 没认真估，至少分为 0.5d / 1d / 3d / 1w 几档 |
| 责任人写"团队" | 一个责任人，否则等于没人负责 |
| 没有粗估行 | 全跳过 back-of-envelope，准备烧掉 50% 时间在错误方向上 |
| 没有中期检查点 | 一条道跑到黑，发现假设跑偏时已无法挽回 |
