# 第 5 步：进行关键分析（Conduct Analyses）

<HARD-GATE>
进入本步骤前必须满足：
- 存在 `docs/strategy/<code>/step-4-workplan.md`
- 工作计划表每行都有"输出形式 + 责任人 + 截止日"

未满足 → 拒绝执行，回退到 step-4。
</HARD-GATE>

## 本步骤的目标

按 step-4 的工作计划，逐个验证 Key Drivers，得出每个假设的"证实/证伪/部分支持"结论，并记录证据、反向证据、So What、不确定性。

**完成的标准**：每个假设都有完整记录，且每个证实的假设都至少检视了 1 条反向证据。

## 方法论核心

1. **先粗后细**：先做 1 小时 back-of-envelope，结果与精细分析对比，让你知道精细化的边际价值
2. **证伪而非证实**：默认你正在自我欺骗——主动找反例，找不到反例的"证实"是不可信的
3. **So What 向上一层**：每个分析结论都要回答"这对焦点问题意味着什么"，不能只停在数据上
4. **意外发现要记录**：分析过程中冒出的、原议题树没覆盖的发现，往往是金矿
5. **证据可追溯**：所有引用的外部数据（数字 / 来源 / 等级）必须落档到独立的 evidence 文件，供 step-6/7 引用与未来复核——分析结论可被推翻，证据档不能丢失

## 引导式对话流程

### Step 5.1 — 复制模板 + 加载工作计划

读取本 skill 同目录下的 `template.md`，复制到 `docs/strategy/<code>/step-5-analysis.md`。

**同时**复制本 skill 同目录下的 `evidence-template.md` 到 `docs/strategy/<code>/step-5-evidence.md`——这是佐证数据档，与 analysis 主档并行维护。

读取 `step-4-workplan.md`，把每个假设填到"总览"表（状态默认"未开始"）。为每个假设预留一个"详细记录"块。

### Step 5.2 — 粗估优先（Back-of-envelope）

如果 step-4 标记了粗估优先项，先做这些。每个假设花 ≤ 1 小时，写出：

- 一个数字 + 推导用到的关键假设
- 推导给出的方向（证实 / 证伪 / 不确定）

填到模板章节 5（粗估优先记录）。

**关键决策**：粗估结果出来后，问用户：

> 粗估给出 [方向] 的信号。是否还需要做精细分析，还是结论已经足够清晰可以跳过？

让用户基于粗估决定是否砍掉某个精细分析（节省时间）。

### Step 5.3 — 逐假设做精细分析

对每个保留的精细分析，用以下结构推进。**每个假设单独一段对话**，避免混淆。

#### 5.3.1 收集证据（支持）

> 假设 H1：「…」
>
> 你已经搜集到哪些支持这个假设的证据？每条说明：内容 + 数据来源 + 信心。

填"关键证据（支持）"小节。

**同时**：把每条引用的外部数据（具体数字 / 来源链接 / 数据等级 A/B/C/D）落到 `step-5-evidence.md` 对应章节。analysis 文档只放结论性引用，evidence 档案保留原始数字与出处。

数据等级定义（通用可信度框架；按场景把"举例"替换为该领域对应来源）：
- **A 一手权威披露**：法定 / 监管 / 官方一手数据，可被第三方独立审计或核验
  - 通用举例：政府统计局、央行 / IMF / 世行、监管机构披露、上市公司财报、官方白皮书、审计报告
  - Web3 / RWA 场景举例：上市加密公司 10-K/Q、监管披露、链上原生事件
- **B 可信第三方研究**：头部研究机构 / 行业基准 / 同行评议学术成果
  - 通用举例：BCG / McKinsey / Gartner / IDC / Statista、行业协会、SSCI 论文
  - Web3 / RWA 场景举例：a16z / Triple-A 等头部赛道研究
- **C 二次推导 / 估算**：基于 A/B 的口径换算、外推、模型测算或专家粗估（必须能复述推导链）
- **D 平台 / 社区 / 信号数据**：第三方监测平台 / 行业媒体 / 社区指标，未经独立审计但可作趋势信号
  - 通用举例：行业仪表板、SaaS 监测、舆情 / 应用商店指标、行业媒体调研
  - Web3 / RWA 场景举例：DeFiLlama / RWA.xyz / DappRadar / Dune

#### 5.3.2 主动找反例（**必做**）

> 现在切换视角：假装你是反对者。哪些证据**反对**这个假设？如果一时找不到反例，给自己 30 分钟主动找一次。
>
> 提示：
> - 找一个反例样本（如失败案例、衰退期数据）
> - 找一个反对意见（如内部反对者、行业怀疑论者）
> - 找一个时间序列上的反向走势

填"反向证据（反对）"小节。**强制至少 1 条**。如果用户坚持"找不到反例"，警告：这通常说明只在做证实，结论不可信。

**同步落档**：反向证据同样落到 `step-5-evidence.md` 的 "关键反向证据汇总" 章节，标注用于反驳哪个假设。

#### 5.3.3 给出最终结论

> 综合支持和反对证据，最终结论是？
>
> - ✅ 证实
> - ❌ 证伪
> - 🟡 部分支持（说明在什么条件下成立）
>
> 信心：高 / 中 / 低（基于证据强度）

#### 5.3.4 写 So What

> 这个结论对**焦点问题**意味着什么？一句话。

挑战用户：如果只写"X 是 Y%"，那是数据；So What 必须是判断（如"市场已饱和"或"扩张窗口仍开放"）。

#### 5.3.5 写不确定性 / 局限

> 这个结论成立的前提条件是什么？数据有什么局限？适用边界在哪？

填"不确定性 / 局限"小节。

### Step 5.4 — 中期检查点

到达 step-4 设的中期检查点日期时，主动触发：

> 中期检查点到了。当前进度：
>
> - 已完成 X / N 个假设
> - 关键发现：……
> - 是否需要调整议题树或砍假设？

把决定填到模板章节 4。如果决定回退到 step-2 重做，明确告诉用户。

### Step 5.5 — 记录意外发现

每完成一个假设，问：

> 在做这个分析时，有没有冒出原议题树没覆盖到的发现？

把意外发现填到模板章节 3。这些发现可能在 step-6 综合时变成新的论点，或者触发回到 step-2 补充假设。

### Step 5.6 — 佐证数据档收尾

在结束 step-5 前，对 `step-5-evidence.md` 做一次完整性检查：

- analysis 中提到的每个外部数字，evidence 档案是否都有对应行？
- 每条数据的 **来源 + 等级（A/B/C/D）+ 链接 / 出处** 是否都填全？
- 是否汇总了反向证据章节？
- 是否列出了 [待内部回填] 清单（依赖内部 BI / 访谈未完成的项）？
- 是否说明了数据风险 / 局限（口径差异、时点、采样偏差）？

这份档案在 step-6/7 引用时会被频繁回查，缺失数据会导致 step-7 财务模型 / 行动建议无法溯源。**evidence 档案不完整 = step-5 不算完成**。

### Step 5.7 — 总览更新 + 自检

把"总览"表的状态、结论方向、信心都更新好。走自检清单。

## 产出物

- 主档案模板：本 skill 同目录 `template.md`
- 佐证档案模板：本 skill 同目录 `evidence-template.md`
- 落盘：
  - `docs/strategy/<code>/step-5-analysis.md`（结论 + 推理）
  - `docs/strategy/<code>/step-5-evidence.md`（数据 + 来源，必须落盘）

## 自检清单（完成门禁）

- [ ] Work Plan 上每个假设都有验证记录
- [ ] 每个证实的假设都有 ≥ 1 条反向证据被检视
- [ ] 每个假设都写了 So What（不只是数据）
- [ ] 中期检查点结果已记录
- [ ] 意外发现单独列出
- [ ] 至少有 1 个粗估优先记录（如果 step-4 安排了）
- [ ] **`step-5-evidence.md` 已落盘**：所有外部数据、来源、等级（A/B/C/D）、反向证据汇总、待回填清单、数据风险都已记录

## 反模式（红旗）

| 红旗信号 | 真相 |
| --- | --- |
| 所有假设都"证实" | 在做证实而非证伪，回去找反例 |
| 反向证据栏写"无" | 没找过；强制花 30 分钟主动找 |
| So What 写成"X 是 Y%" | 那是数据不是判断；改写成判断句 |
| 数据精确到小数点后 4 位 | 假精确，输出精度匹配输入精度 |
| 没有意外发现 | 没看仔细或没记录；分析中一定有意外 |
| 跳过中期检查点 | 一条道跑到黑，无法挽回错误方向 |
| 数据只在 analysis 行文中、未落 evidence 档案 | 三个月后没人能复核；强制独立落档 `step-5-evidence.md` |
| evidence 档案只列数字、不标来源 / 等级 | 不可追溯 = 不可信；每行必须有出处和 A/B/C/D 等级 |

## 完成后交接

向用户输出：

> ✅ Step-5 完成。共 N 个假设：
> - 证实 X 个 / 证伪 Y 个 / 部分支持 Z 个
> - 意外发现 K 个
>
> 下一步进入 **step-6: 综合调查结果**——把分散的结论用金字塔结构向上归纳，形成 3 个核心论点支撑主结论。预计 20-30 分钟。
>
> 继续吗？

确认后，调用 `step-6-synthesize` skill。

输入给下一步：
- `<code>`
- `step-5-analysis.md` 路径
- `step-5-evidence.md` 路径
- 假设结论汇总（每条假设的最终结论 + So What）
- 意外发现清单
